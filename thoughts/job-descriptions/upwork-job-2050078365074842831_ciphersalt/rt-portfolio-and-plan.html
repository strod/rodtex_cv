M1
Data Foundation & Salt Score Engine
30% complete · 30% payment
Get raw inputs out of AMC, unify the three-tier data structure, ship a working "black box" Python scorer on real CSVs.
  • AMC extraction pack — documented SQL queries pulling Direct Data (Impressions, Deterministic Reach, Conversions) plus inputs for Derived Data (Path Depth, Revenue Velocity, New-to-Brand). Versioned CSV outputs.
  • Three-tier data dictionary — one-page schema mapping each of the 17 metrics to Direct / Derived / Synthesized origin, with formula + source field for every Derived metric.
  • Join engine (Python) — ingests Procurement and Performance CSVs, normalizes supplier keys, resolves duplicates → single supplier-level dataframe ready for scoring.
  • Salt Score v1 script — parameterized weighting engine, Moneyball rules in a swappable config file, outputs a per-supplier Scorecard CSV.
  • QA tick-and-tie sheet — 3–5 suppliers traced raw AMC field → derived metric → weighted contribution → final Salt Score, end-to-end.
Acceptance python score.py on provided CSVs produces a Scorecard whose top/bottom suppliers pass the founder's smell test; any score traceable in under a minute.

Section 6 Confirmations · Compressed Answers
Q1 · v0.app handoff & design refinement
Treat v0 as a layout sketch, not a codebase. Pass 1: extract typography, spacing, color tokens into a design system. Pass 2: replace ad-hoc components with composable primitives. Pass 3: wire RSC data, strip the client-side fetch boilerplate v0 over-generates. Result: bespoke, premium feel, no AI-generated tells.
Q2 · RSC & sub-second "Financial Terminal" feel
FastAPI service exposes two surfaces: batch pre-compute (steady views) + on-demand recompute (dial). Server Components handle CSV aggregation server-side; Client Components only where interaction demands it. Pre-compute the Scorecard at ingest → dial stays under 800 ms at POC volumes.
Q3 · CSV-to-UI pipeline (dial → Python → render)
User turns dial → Client Component fires server action with new weights → FastAPI recomputes Salt Score against the in-memory CSV pool → returns updated Scorecard rows → RSC streams re-rendered Situation Room with optimistic UI. Every step instrumented for audit.
Q4 · Vercel AI SDK / streamUI for agent explanations
Agent reads the Scorecard, identifies the top weighted contributors per supplier, and uses streamUI to render a custom explanation component (bar of metric weights, deltas vs peer set, narrative caption). No prose walls — every number renders as a structured, on-brand element.
Q5 · GUI tooling beyond v0.app
v0 + Next.js stays the backbone for the agentic feel. Figma added only as a design-system reference layer. Streamlit is rejected — fast to ship but won't deliver terminal-grade response or bespoke aesthetic the brief calls for.
Q6 · QA & tick-and-tie
Every milestone review ships with a written audit sheet: 3–5 suppliers traced raw AMC field → derived metric → weighted contribution → final Salt Score. Unit tests on the scoring module, edge-case sweep before founder review, regression check that identical input yields identical score.
